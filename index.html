One engine, three memory budgets

Enigmus runs the same MLX engine on iPhone, iPad and Mac. What changes is how much memory a model can take: the model list accepts a model when its weights fit in about two-thirds of the device's RAM, leaving the rest to the system and to the KV cache that grows with each conversation.

New in Enigmus 1.3

OpenAI-compatible API

LLM Server for macOS and iOS

Enigmus can serve the loaded model over an OpenAI-compatible API on the device itself. Scripts, coding agents and browsers send requests to a local address, the same MLX engine as the in-app chat generates the reply, and nothing passes through a cloud service. The server is off by default.

bash
curl http://127.0.0.1:31415/v1/chat/completions \
  -H "Content-Type: application/json" \
  -d '{"model": "enigmus", "messages": [
        {"role": "user", "content": "Hi"}]}'

Scripts and notebooks

The openai SDK works with its base URL set to the server. The model name enigmus always means the loaded model.

Coding agents

Tool calling is served on Qwen 3.5 2B and up and on Qwen 3.6, so agents built on the OpenAI chat API, opencode among them, run against a local model. Source code stays on the machine.

Browser chat

A web chat is served at / on the same port. Any browser that can reach the address gets a chat page with nothing to install; its conversations stay in that browser.

Mac as the model host

With Allow Network Access, an iPad or iPhone on the same network can use a model too large for its own memory, served from a Mac that stays out of idle sleep while serving.
